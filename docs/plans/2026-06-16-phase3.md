# Phase 3 — risk-scored PR review + `illuminate-eval` + GitNexus query surface

**Status:** planned (2026-06-16). Design produced by a study→synthesize→critique
workflow; this doc is the *reconciled* plan with the adversarial critique's
verified fixes folded in. Critique verdict was **ready-with-fixes** — the fixes
are applied below and called out as **[critique fix]**.

## What Phase 3 delivers

Three capabilities on illuminate's existing two-DB substrate (`graph.db`
decision graph + `index.db` code graph) with **no new infrastructure** — every
deliverable runs cold per-call over the two SQLite files, makes zero network
calls in its core path, and is byte-stable for identical inputs:

- **(a) Risk-scored review** — a deterministic risk score folded additively into
  `AuditResult`, plus an offline `illuminate review` CI merge-gate.
- **(b) `illuminate-eval`** — a pure, offline, deterministic parse-and-score
  crate ported from rohansx/reflect (MIT, license verified in-hand 2026-06-16).
- **(c) GitNexus-style query surface** — a bounded openCypher-subset query
  (`illuminate cypher`) + directional process-flow tracer (`illuminate trace`)
  over `index.db`, re-implemented from the public openCypher grammar (NOT derived
  from GitNexus source, which is npm-only / license-unverified).

## Design rules (corrected per critique)

- **Extend before adding.** Risk scoring is a ~50-line pure fold over fields
  `AuditResult` already carries — it lives in `illuminate-audit` as an additive
  `#[serde(default)] risk: Option<RiskScore>`, **not** a new crate.
- **Decoupling exemplar = `illuminate-wiki`** (zero `illuminate-core` dep, closure-wired).
  **[critique fix]** `illuminate-route` is NOT the model — it has a typed
  `use illuminate::Graph` (route/lib.rs:8). Precise rule:
  - `illuminate-eval` MUST be a true zero-`illuminate-*` leaf (so both audit and
    reflect can depend on it without a cycle).
  - `illuminate-query` legitimately takes a **typed** `illuminate-index` path dep
    (it compiles SQL over the `index.db` schema) — it's a typed *acyclic* consumer,
    exactly like `illuminate-audit`. Not "closure-wired."
- **Honest substrate limits — three lens ideas REJECTED for the MVP:**
  - `EdgeKind::Tests` / transitive test-coverage deficit — no `TESTED_BY` edge and
    no symbol-resolution pass exists (`edge_extract.rs` stores call targets as
    literal text like `self.method`), so a test→prod heuristic is noise. The CRG
    test-deficit term (0.30 of its budget) hangs on this. **[critique fix]** A real
    symbol-resolution pass is a **Phase-4 epic**, not a small follow-up.
  - cross-community risk term — the `communities` table is in `graph.db` (decision
    graph); `index.db` has no per-symbol cluster id, so it'd always return None.
  - churn/co-change as a live read — non-deterministic across commits (violates
    determinism). Only a frozen index-time snapshot is acceptable — **deferred to
    Phase 4**; **[critique fix]** column-level schema intentionally omitted here so
    nobody ships it under MVP pressure.
- **Naming reality:** `illuminate query` already = decision-graph FTS search →
  the Cypher verb is **`illuminate cypher`**. The MCP `impact` tool already =
  anchor-walk over `graph.db` → code-graph tools get new names
  (`illuminate_cypher`, `illuminate_trace`, `illuminate_review`).
- **Exit codes — [critique fix]:** exit **4 is already `illuminate trust-check`**
  (trust_check.rs:56). Risk-gate breach uses **exit 5**. Slice 4 publishes a full
  exit-code matrix in `docs/AUDIT.md`: 0 pass · 1 generic err · 2 violation ·
  3 warning · 4 trust-check failed · 5 risk-gate breach.

## New crates (only two justified)

| Crate | Purpose | Deps | Coupling |
|-------|---------|------|----------|
| `illuminate-eval` | pure offline deterministic parse-and-score (EvalSignal/Severity verdict model, 4 stdout parsers behind a `Parser` trait, regex `PatternEngine`, Laplace `confidence_score`, strsim near-dup gate, `Outcome`/`GateStatus` folds onto `AuditStatus`). Never spawns a process, never touches SQLite/network. | serde, serde_json, regex, strsim (all workspace) | **true leaf** — zero `illuminate-*` deps (so audit + reflect both depend on it, no cycle) |
| `illuminate-query` | openCypher-subset parser + AST + read-only SQL-compiling executor over `index.db` | `illuminate-index` (path), rusqlite, serde, serde_json | typed acyclic `illuminate-index` consumer (like audit) |

## Schema deltas

- **`index.db`: NONE for the MVP.** `trace_flow`, `resolve_qn_to_symbols`,
  `contains_within`, the Cypher executor, and risk scoring all run over the
  existing `symbols` + `edges` tables and existing `idx_edges_*` / `idx_symbols_*`
  indexes. No ALTER, no new table.
- **`graph.db`: NONE.** The bi-temporal decision graph is untouched.
- **`AuditResult` JSON: additive only** — `#[serde(default)] pub risk: Option<RiskScore>`.
  Old payloads deserialize with `risk=None` (same pattern as `default_confidence`).
- **Deferred (Phase 4+), schema intentionally NOT specified here:** `file_churn` /
  `co_change` frozen-snapshot caches; `kind='tests'` edges.

### Slice 1 — QN resolution + **directional** flow tracing + fixture builder *(the in-tree de-risk)*
- `resolve_qn_to_symbols` (split on `::`/`.`/`->`, last-segment match on
  `symbols.name`, file-scoped when possible — same best-effort strategy
  `CodeIndex::enrich_anchor` uses).
- **[critique fix]** `trace_flow` is **directional** and needs a per-`FlowDir` CTE
  — NOT a verbatim reuse of `impact_radius` (storage.rs:362-379), which is
  *bidirectional* (both UNION branches unconditionally). Borrow only the
  temp-seed-table + probe-limit+1 truncation idiom. `FlowDir{Downstream,Upstream,Both}`,
  `FlowStep`, `FlowResult` in `edges.rs`.
- **[critique fix]** Add a **fixture-builder helper** (in-memory `Connection` +
  `create_schema` + known symbols/edges, mirroring the `diagram_reader_tests`
  `open()/sym()/import_edge()` helpers at storage.rs:419-447) that downstream
  slices reuse.
- **Touches:** `illuminate-index/src/edges.rs`, `illuminate-index/src/storage.rs`.
- **Accept:** `cargo test -p illuminate-index` green; deterministic, capped,
  kind-filtered steps; **test that `dir=Both` reproduces the existing
  `impact_radius` impacted set**; no schema change.

### Slice 2 — `illuminate trace` CLI + `illuminate_trace` MCP *(end-to-end before the parser)*

### Slice 3 — risk scoring as a deterministic fold into `AuditResult` *(highest-value, lowest-coupling)*
- `RiskScore`/`RiskBand{Low,Medium,High,Critical}` (with `from_score` +
  `fails(gate)`)/`RiskFactor` in `response.rs`; `Auditor::review_pr` calls
  `audit_with_files` then `fold_risk(&AuditResult)->RiskScore`: capped weighted sum
  over signals `AuditResult` ALREADY carries (max severity, `count(impacted_symbols)`,
  `truncated`, frozen-path policy hits, `sum(confidence)`). Dominant-severity roll-up,
  additive/capped to clamp 0..1.
- **[critique fix]** Pin the **surviving weight table** in `docs/AUDIT.md` (the
  0.40/0.70/0.85 band ladder must be recalibrated *without* the dropped Tests-deficit
  0.30 + cross-community terms) and back it with a **pinned-output test**.
- **Touches:** `illuminate-audit/src/response.rs`, `illuminate-audit/src/lib.rs`,
  `docs/AUDIT.md`. No new crate.
- **Accept:** `cargo test -p illuminate-audit` green; pure pinned deterministic
  fold; existing audit JSON consumers unaffected (additive field).

### Slice 8 — `illuminate-query` *(split per critique into 4 green sub-slices)*
Bounded subset: single `MATCH` (node OR 1-hop rel OR bounded var-length `*1..N`,
N≤6), optional `WHERE` (AND-chained `=`,`<>`,`CONTAINS`,`STARTS WITH`,`IN` on bound-var
props), `RETURN` + `ORDER BY` + `LIMIT`. Labels→`symbol_type`+synthetic `File`;
rel types→`EdgeKind`. Parameterized SQL only; var-length reuses the recursive-CTE shape.
- **8a** — hand-rolled recursive-descent parser + AST + precise reject-errors (parse-only tests).
- **8b** — NodeOnly + 1-hop executor over the resolver (read-only).
- **8c** — bounded var-length + truncation.
- **8d** — `illuminate cypher` CLI + `illuminate_cypher` MCP.
  **[critique fix]** the MCP tool opens a **fresh cold `rusqlite::Connection` per call**
  with `PRAGMA query_only=ON` (matching the CLI path) — it MUST NOT reuse the resident
  shared `index_conn` (tools.rs:123 `OnceLock<Mutex<Connection>>`), because that handle
  is neither cold nor safe to mutate with a sticky `query_only` (it backs `audit_with_files`).
- **Touches:** `illuminate-query/Cargo.toml`, `illuminate-query/src/{lib,ast,parse,exec}.rs`,
  `illuminate-cli/src/commands/cypher.rs` + `lib.rs`, `illuminate-mcp/src/{tools.rs,server.rs}`.
- **Accept:** `illuminate cypher "MATCH (f:Function)-[:calls*1..3]->(g) RETURN g.name LIMIT 20"`
  returns stable rows; out-of-subset input errors clearly; `illuminate_cypher` in tools/list;
  `cargo test --workspace` green.

## Deferred to Phase 4+ (explicitly not Phase 3)
- Real qualified-name **symbol-resolution pass** over free-text edge endpoints
  (root cause of shallow traversal; multi-week epic).
- `EdgeKind::Tests` + transitive test-coverage-deficit risk term (depends on the above).
- `file_churn` / `co_change` frozen-snapshot caches + the cross-community risk term.
- `illuminate review --head <ref>` arbitrary-range diff.
- A dedicated `illuminate eval run <cases>` golden-fixture harness.

## Risks
- QN resolution over free-text edges is best-effort; multi-hop traces can be
  shallow/noisy. Slice 1 must be honest about caps and prove determinism.
- openCypher subset must reject cleanly outside its grammar (no silent partial eval).
- Each new crate must hold the low-coupling line (eval = leaf; query = typed-acyclic).
